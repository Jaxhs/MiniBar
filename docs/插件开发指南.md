# MiniBar 插件开发指南

宿主只认识 `MiniBar.Sdk` 里的接口。插件是一个普通类库，编译出一个 DLL，丢进插件目录即可。

---

## 1. 最小可运行插件（完整工程）

**`MyPlugin.csproj`**

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <AssemblyName>MyPlugin</AssemblyName>
    <!-- 直接编译进宿主的插件目录，方便调试 -->
    <OutDir>..\MiniBar\src\MiniBar.App\bin\$(Configuration)\Plugins\</OutDir>
  </PropertyGroup>
  <ItemGroup>
    <!-- Private="false" 非常关键：契约程序集由宿主提供。
         如果插件目录里出现 MiniBar.Sdk.dll 的副本，插件会被加载成"另一套 IMinibarPlugin"，
         宿主 for 循环里的 is IMinibarPlugin 判定会直接失败，插件加载不起来。 -->
    <ProjectReference Include="..\MiniBar\src\MiniBar.Sdk\MiniBar.Sdk.csproj" Private="false" />
  </ItemGroup>
</Project>
```

**`MyPlugin.cs`**

```csharp
using System.Windows;
using System.Windows.Controls;
using MiniBar.Sdk;

namespace MyPlugin;

[PluginManifest(
    id: "demo.myplugin",            // 全局唯一，持久化固定顺序/启用状态都以它为准
    name: "我的插件",
    Description = "一句话说明",
    Author = "me",
    Version = "1.0.0",
    Icon = "emoji:🎯",              // 图标语法见第 3 节
    Order = 100,                    // 初次安装时的排序权重
    DefaultPinned = true)]          // 首次发现时是否固定到任务栏
public sealed class MyPlugin : IMinibarPlugin, ITaskButtonPlugin, IPanelContentPlugin
{
    private IPluginContext _context = null!;

    // ---- IMinibarPlugin ----

    public void Initialize(IPluginContext context)
    {
        _context = context;
        // 插件专属可写目录，宿主保证存在
        _context.Logger.Info($"数据目录：{context.DataDirectory}");
    }

    public void Dispose()
    {
        // 一定要在这里退订事件、停计时器，否则 ALC 无法被回收（内存泄漏）
    }

    // ---- ITaskButtonPlugin ----

    public PluginIcon Icon => "emoji:🎯";
    public string DisplayName => "我的插件";
    public string? Badge => null;
    public void OnClick(BarItemClickContext context) => context.TogglePanel();

    // ---- IPanelContentPlugin ----

    public string PanelTitle => "我的插件";
    public double PreferredWidth => 360;
    public double PreferredHeight => 260;

    public FrameworkElement CreateContent(IPanelHost host)
    {
        var button = new Button { Content = "点我" };
        button.Click += (_, _) => _context.Shell.Notify("来自插件的一次通知", NotificationKind.Success);
        return button;
    }

    public void ReleaseContent()
    {
        // 面板已关闭：释放大对象、停止计时器
    }
}
```

编译 → 把 DLL 拖到任务栏上（或复制进 `%LOCALAPPDATA%\MiniBar\Plugins`）→ 图标立刻出现。

## 2. 生命周期约定（很重要）

| 时机 | 宿主会做什么 | 插件应当做什么 |
| --- | --- | --- |
| 发现阶段 | 只读程序集元数据，**不实例化**，探测完立刻卸载探测上下文 | 什么都不用做 |
| 启用 | `new()` → `Initialize(context)`，全程 UI 线程 | 只做轻量初始化；耗时任务异步 |
| 禁用 | `Dispose()` → 卸载 ALC → 两轮 GC → 归还内存 | 在 `Dispose` 里彻底断掉引用（事件、计时器、静态字段） |
| 删除 | 先卸载，再删除 DLL（含空目录） | 无 |
| 面板打开 | `CreateContent(host)` | 每次都新建内容，不要缓存跨次使用的宿主对象 |
| 面板关闭 | `ReleaseContent()` + 释放窗口内容 | 停计时器、断开事件 |
| 内嵌内容挂载 | `CreateBarWidget()`（每插件只调一次） | 返回的元素由自己负责刷新 |
| 主题切换 | 触发 `IPluginContext.ThemeChanged` | 重新取色（或干脆在界面里用 `context.Theme` 每次读） |
| 迷你模式 | `CreateCompactContent()` / `ReleaseCompactContent()` | 紧凑内容要极简、只读、不抢焦点 |

> 经验法则：**只有"正显示着"的界面才持有计时器和大对象**。示例里的时钟插件就是这样
> —— 任务栏内嵌读数、面板、迷你内容三处各自持有引用，全都不在时立刻停掉 `DispatcherTimer`。

## 3. 图标语法

`PluginIcon` 支持字符串隐式转换，直接写字符串最省事：

| 写法 | 含义 |
| --- | --- |
| `"emoji:🕒"` | Emoji / 任意短文本 |
| `"glyph:E823"` | Segoe Fluent Icons / Segoe MDL2 码点（4~6 位十六进制） |
| `"glyph:★"` | 直接给字符 |
| `"file:C:\icons\a.png"` | 本地图片（按显示尺寸解码，不会整图读进内存） |
| `"uri:pack://application:,,,/res/a.png"` | pack / http 图片 |

## 4. 宿主能力（`IPluginContext` / `IShellService`）

```csharp
context.PluginId             // 清单里的 id
context.PluginDirectory      // 插件 DLL 所在目录（可能只读）
context.DataDirectory        // 插件专属可写目录
context.Logger               // Info/Warn/Error/Debug（会带插件前缀写入宿主日志）
context.Theme                // PluginTheme：Background/Surface/Foreground/Muted/Border/Accent/Danger
context.IsMiniMode           // 当前是否迷你模式
context.InvalidateBarItem()  // 图标/徽标/提示变了，请宿主刷新（同帧内合并）
context.GetSetting<T>(key, defaultValue) / SetSetting<T>(key, value)
context.CreateWindow(...)    // 在屏幕任意位置弹自己的浮窗

context.Shell.OpenPanel(id) / ClosePanel / TogglePanel / CloseAllPanels
context.Shell.EnterMiniMode(id) / ExitMiniMode() / SetMiniModePlugin(id)
context.Shell.Notify("文字", NotificationKind.Success)
context.Shell.LoadPlugin(dllPath) / UnloadPlugin(id, deleteFile) / SetPluginEnabled(id, bool)
context.Shell.GetPlugins() / UserPluginDirectory / ShowPluginManager() / ShowMainMenu()
```

**取色**：插件不要依赖宿主的资源字典，用 `context.Theme` 的语义色：
`Foreground / Muted / Surface / Border / Accent / AccentForeground / Danger / Background`（`#AARRGGBB`）。

## 5. 拖放处理的优先级

`IShellService.HandleDrop` 的询问顺序：

1. 拖到某个**图标**上时，先问该图标对应的插件（`context.Target == BarItem`，`TargetPluginId == 该插件`）；
2. 再按安装顺序依次问所有实现了 `IDropHandlerPlugin` 的插件；
3. 有插件把 `context.Handled = true` 就停止传递；
4. 都不处理时走内置兜底：单个 `.dll` → 热加载插件；其它 → 弹提示。

所以：

* `CanHandle` 要**快且无副作用**（会被频繁调用，拖拽时每次移入都会问）；
* 想让宿主处理 DLL，就在 `CanHandle` 里对单个 `.dll` 返回 `false`；
* 示例「便签」只认领 `.txt/.md/.log/.csv`，「快捷启动」认领其余文件/文件夹 —— 二者顺序由
  安装顺序决定（`minibar.notes` Order=20 在 `minibar.launch` Order=30 之前，所以文本文件会被便签先认领）。

## 6. 全局快捷键

```csharp
public IEnumerable<PluginHotkey> GetHotkeys()
{
    yield return new PluginHotkey("toggle", "Ctrl+Alt+N 打开/关闭便签",
        HotkeyModifiers.Control | HotkeyModifiers.Alt, Key.N);
}

public void OnHotkey(string hotkeyId) { /* 在 UI 线程回调 */ }

public void OnHotkeyRegistrationFailed(string hotkeyId, string reason)
{
    // 组合键被别的程序占用时回调（例如 Ctrl+Alt+1 常被输入法/显卡驱动抢占）
}
```

快捷键在插件加载时注册、卸载时自动注销。**不要在插件里自己 P/Invoke `RegisterHotKey`**，
否则宿主无法帮你处理冲突，也会在卸载时留下系统级残留。

## 7. 让插件拥有设置项（ISettingsPlugin）

宿主设置窗口会自动列出所有实现了 `ISettingsPlugin` 的插件。插件只需要声明"有哪些设置项、
怎么读、怎么写"，渲染与读写都由宿主完成：

```csharp
public sealed class MyPlugin : IMinibarPlugin, ISettingsPlugin
{
    private IPluginContext _context = null!;
    private DispatcherTimer? _timer;
    private double _interval = 2;

    public void Initialize(IPluginContext context)
    {
        _context = context;
        _interval = context.GetSetting("IntervalSeconds", 2d);
    }

    public IEnumerable<PluginSettingsSection> GetSettingsSections()
    {
        yield return new PluginSettingsSection
        {
            Title = "我的插件",
            Description = "改完立即生效，配置由宿主保存",
            Icon = "emoji:🎯",
            Items = new[]
            {
                // 工厂写法：值自动写进插件配置，onChanged 里做即时生效
                PluginSettingItem.Toggle(_context, "ShowDetail", "显示详细信息", true,
                    "关闭后任务栏只显示汇总数字", UpdateBarText),

                PluginSettingItem.Number(_context, "IntervalSeconds", "刷新间隔", 2,
                    1, 30, 1, "秒", "间隔越短越及时",
                    () =>
                    {
                        _interval = _context.GetSetting("IntervalSeconds", 2d);
                        _timer?.Stop();
                        _timer = null;
                    }),

                PluginSettingItem.Choice(_context, "Mode", "模式", new[] { "简洁", "标准", "详细" }, "标准"),

                // 想完全自己控制就手写 GetValue/SetValue（示例 Clock 插件就是这么做的）
                new PluginSettingItem
                {
                    Label = "数据文件",
                    Kind = PluginSettingKind.File,
                    Description = "宿主会给出「浏览…」按钮",
                    GetValue = () => _context.GetSetting("DataFile", string.Empty),
                    SetValue = value =>
                    {
                        _context.SetSetting("DataFile", value as string ?? string.Empty);
                        PluginSettingItem.Applied(_context, Reload); // 回调解 + 刷新任务栏图标
                    },
                },

                PluginSettingItem.Button("立即执行一次", DoWork, "说明文字"),
                PluginSettingItem.Note("这行只是说明文字，不参与存储。"),
            },
        };
    }
}
```

要点：

* `Kind` 决定宿主画什么控件：`Bool` → 开关，`Number` → 滑块 + 数值，`Choice` → 下拉框，
  `Text` → 输入框，`Folder`/`File` → 输入框 + "浏览…"，`Action` → 按钮，`Info` → 说明文字。
* 值默认存在插件的配置里（`context.GetSetting/SetSetting`，落盘在 `%APPDATA%\MiniBar\settings.json`），
  所以宿主不需要知道插件是怎么存配置的。
* 工厂方法的 `onChanged` 回调里做"即时生效"（重开计时器、刷新界面等）。
* 手写 `GetValue/SetValue` 时用 `PluginSettingItem.Applied(_context, onChanged)` 收尾，
  它会调用你的回调并让宿主刷新任务栏图标/提示。
* `GetSettingsSections()` 每次渲染都会重新调用，所以 `GetValue` 必须返回**当前值**（用闭包读设置即可）。
* 宿主自己的设置（主题、边缘、AppBar、迷你模式、内存策略…）用的是同一套模型，
  所以插件设置页和宿主设置页的外观、交互完全一致。

## 8. 常见坑

| 现象 | 原因 / 解法 |
| --- | --- |
| 插件图标不出现，日志写「不是 MiniBar 插件」 | 忘了加 `[PluginManifest]`，或没有公共无参构造函数 |
| 加载时抛 `InvalidCastException` / `is IMinibarPlugin` 为 false | 插件目录里带了 `MiniBar.Sdk.dll` 副本 → 去掉（`Private="false"`） |
| 禁用后内存不降 | `Dispose` 里没断引用（事件、`DispatcherTimer`、静态字段）；`DispatcherTimer` 必须 `Stop()` 并置空 |
| `Assembly.Location` 为空 | 宿主按字节流加载，程序集没有磁盘位置。要用目录就取 `context.PluginDirectory` |
| 面板里的计时器一直跑 | `ReleaseContent()` 里没停 —— 面板关闭时宿主只会清空内容，不会替你停计时器 |
| 拖放没有生效 | `CanHandle` 返回了 false，或忘了设置 `context.Handled = true` |
| 内嵌内容刷新太频繁导致 CPU 高 | 降低计时器频率；只在实际变化时调用 `InvalidateBarItem()` |
| 全屏时迷你窗口抢了游戏焦点 | 不要设 `MiniWindowAcceptsFocus = true`；紧凑内容别放需要键盘的控件 |
| 深色主题下自己 new 出来的控件"看不见" | 宿主给 `TextBlock` 设了主题前景色（深色主题下接近白色），而 `ComboBox`/`TextBox` 这类控件的**系统默认模板是浅色的**，于是白底白字。插件自绘控件时请用 `context.Theme` 的语义色自己设背景+前景（示例插件的 `MakeButton` 就是这么做的），或者直接用宿主已经主题化过的 `TextBlock`/`Grid`/`Border` |

## 9. 调试

* 宿主日志：`%APPDATA%\MiniBar\logs\minibar.log`（含插件前缀、异常堆栈；`settings.json` 里
  `VerboseLogging = true` 可打开 Debug 级日志）。
* 设置窗口的「插件管理」页（`Ctrl+Alt+P` 或任务栏右键 → 设置…）能看到每个插件的状态、能力、文件路径与加载错误，
  并提供「打开界面 / 固定 / 启用禁用 / 重新加载 / 打开设置 / 卸载并删除」按钮，
  还有「从文件加载…」「全部重新加载」「重新扫描目录」与使用说明 —— 调试热插拔时不必重启宿主。
* 直接删除运行中的插件 DLL（或把文件挪走）可以验证热卸载：宿主会卸载它并在日志里记录，
  把文件放回来又会自动加载并恢复原来的固定位置。
